# Login Ads and Login/Register Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the login and register pages in the light "Option A" look. Their left
side becomes an advertisement slider whose slides the platform admin manages from a
new Login Ads tab.

**Architecture:**

- **Storage:** one new table in the main database (`dbo.LoginAds`) with seven stored
  procedures, in script 25.
- **Rules:** a pure `LoginAdRules` class holds every validation rule.
- **Service:** `LoginAdService` (a `BaseRepository` on `MainDbHelper`) serves two
  controllers:
  - an anonymous `LoginAdsController` for the login and register pages
  - admin actions added to `PlatformController`
- **UI:** a shared standalone Angular `LoginAdSliderComponent` is used by both
  pages. A new tab in `platform-admin-component` manages the slides.

**Tech Stack:** SQL Server, ASP.NET Core (.NET), xUnit, Angular (standalone, signals),
vitest.

**Spec:** `docs/superpowers/specs/2026-10-19-login-ads-design.md`
**Mockup:** https://claude.ai/artifact/RhSX1L6LXADgjKCsv4kpHU ("Option A: Light",
"SaaS admin: Login ads")

## Global Constraints

**SQL**
- Every SQL change is a new numbered file. Never edit an existing SQL file. The new
  script is `EncryptzAPI/Database/MainDB/25_Login_Ads.sql`.
- Do **not** run any script against the server in `appsettings.json`; it is LIVE.
  Building and testing must not touch a database.
- Do not stage `EncryptzAPI/appsettings.json`, which has local changes.

**Images**
- Images are JPG, PNG or WebP only, at most 2 MB (`2 * 1024 * 1024` bytes). The
  type is checked by extension and by magic number on the server.
- Images are served with a content type from our own list and the header
  `X-Content-Type-Options: nosniff`.

**Fields**
- Field limits: Tag 40, Title 120, Body 250, ButtonText 30, LinkUrl 500, image name
  200.
- Links: empty, or an absolute `http://` or `https://` address. This is checked on
  save and again before rendering.

**Look**
- Colours: red `#D42B2B`, navy `#1B4A7A`, text `#14213D`, muted `#5A6A7E`, borders
  `#D5DCE6`, page background `#F4F6FA`. Font: DM Sans.

**Login and register behaviour**
- Login and register behaviour is unchanged: the bindings, the forgot-password OTP
  flow, the location-logout banner, error messages and `autocomplete` values.
- The form never waits for the ads.
- Below 820px the slider is hidden and the ads are not fetched.

**Code style**
- Commit messages are in the style of the repository (a plain sentence), ending
  with the `Co-Authored-By` line.

## Review Focus

1. **Bad image file:** the admin uploads a `.png` that is really a PDF, or a file
   just over 2 MB. It must be refused with a clear message, and nothing is saved
   (Task 2 tests).
2. **Ended or future ad requested directly:** an ad's `ShowUntil` passed yesterday,
   or its `ShowFrom` is tomorrow, and someone opens its image URL directly. The
   answer must be 404 and the slide must not be listed (Task 1 script test on the
   date filter; Task 4 test on `onlyShowing`).
3. **API down when the login page loads:** the form must still work, and the
   slider shows the fallback slide (Task 5 test: an error gives the fallback).
4. **Malicious link:** a link like `javascript:alert(1)` is stored by somebody
   editing the database directly. The slider must not render it as a link (Task 5
   test).
5. **Image-only slide:** no headline, no text and no button. It must show the bare
   image with no empty pill or button (Task 5 test).

| Procedure | Parameters | Returns |
|---|---|---|
| `dbo.sp_LoginAd_ListPublic` | none | `LoginAdId, Tag, Title, Body, ButtonText, LinkUrl, ImageVersion`, only slides shown today, ordered by `SortOrder, LoginAdId` |

| `dbo.sp_LoginAd_Save` | `@LoginAdId INT` (0 = new), `@Tag, @Title, @Body, @ButtonText, @LinkUrl, @ShowFrom DATE NULL, @ShowUntil DATE NULL, @IsActive BIT, @ImageName NVARCHAR(200) NULL, @ImageType NVARCHAR(20) NULL, @Image VARBINARY(MAX) NULL, @UserId INT` | `Success BIT, Message NVARCHAR, LoginAdId INT` |

| `dbo.sp_LoginAd_Reorder` | `@Ids NVARCHAR(MAX)` (a JSON array of ids), `@UserId` | `Success, Message` |

How `sp_LoginAd_Save` behaves:
- A new slide gets `SortOrder = MAX + 1`.
- A new slide with a NULL `@Image` fails with the message "Choose an image".
- On update, a NULL `@Image` keeps the stored image. A new image sets
  `ImageVersion = ImageVersion + 1`.

match that shape so `ToResult` and `ToFlag` keep working.

- **`GetImage`:** returns null when there is no row.
- **Logging:** log `Information` on save, delete and reorder, with the user id.
